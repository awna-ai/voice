# VO16.6b1: Voice pins Radio v0.3.0

Card: VO16.6b1 (split from VO16.6b, 2026-11-17). Small. Branch `lane-v1/VO16.6b1`, off `origin/main` `d5c7d59`.

## Why

Radio `v0.3.0` (commit `09f499a6519ea4c0e92340d861a7ad294849c689`, socket protocol 1.11) is the release that carries
deliberations. Voice still pins `v0.2.0` (protocol 1.7) for the two crates it builds against and for the `radio`
binary it ships inside Voice.app. This slice moves all three to `v0.3.0` together, so one Radio commit is in
`Cargo.lock` and the bundled daemon matches the client. It changes no panel behaviour: `crates/radio-panels` is
byte-identical between the two tags (`git diff --stat v0.2.0 v0.3.0 -- crates/radio-panels` is empty), and
`crates/radio-client` only adds the deliberation types and `PROTOCOL_MINOR` goes from 7 to 11.

## The one behaviour that changes, on purpose

`voice_api::radio::Radio::hello` (`builder/api/src/radio.rs`) refuses a daemon whose `protocol.minor` is below
`radio_client::PROTOCOL_MINOR`. After the bump that constant is 11, so Voice refuses a 1.7 to 1.10 daemon with
`text::TOO_OLD`. **Keep that check exactly as it is.** It is the contract's rule: an install never replaces a
newer daemon with an older one, so the daemon is never older than the copy an app bundles, and Voice runs its
bundled install on every start (VO16.6a). Do not add a Voice-side minimum.
