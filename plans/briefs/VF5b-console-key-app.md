# VF5b brief: Connect Claude takes a pasted Console API key on a Mac (API, app and screen)

VF5a (already in this working tree, `plans/briefs/VF5a-console-key-agent-cli.md`) made the agent and
the CLI take a pasted Anthropic Console API key on a Mac: `claude::takes_key(SignIn::Console)` is true
on a Mac, `Claude::save_key(self, home, key: Secret) -> Result<Claude>` keeps it in Voice's Keychain
item and checks Claude Code accepts it, `Claude::sign_out` forgets it, and every later run passes it as
`ANTHROPIC_API_KEY`. `text.rs` has the sentences (`KEY_HOW`, `KEY_SHAPE`, `KEY_NOT_KEPT`,
`KEY_UNREADABLE`, `KEY_NOT_FORGOTTEN`, `KEY_REFUSED`, `CONSOLE_TAKES_KEY`) and the API allow-list
(`builder/api/src/assistants.rs` `claude_message`) already passes them through.

This brief gives the app the same: an API function, a Tauri command, and a key field on the Connect
Claude screen in place of the Console button, on a Mac only. Off a Mac nothing changes.

Read first: `AGENTS.md`, `.ai/PROJECT.md`, `.ai/SECURITY.md`, `CONTRIBUTING.md`, VF5a's brief,
`builder/api/src/assistants.rs` (from `ready_status` to `claude_sign_in_shutdown`),
`builder/api/src/dto.rs` (`ClaudeStatus`, `ClaudeSignInRequest`), `builder/api/src/parity.rs`,
`builder/app/src/commands.rs`, `builder/app/src/main.rs`, `builder/app/src/command_names.rs`,

## 1. Decisions already made (do not change them)

1. **`ClaudeStatus` gains `pub console_takes_key: bool`** (doc: "The Console sign-in on this computer
   is an API key the person pastes (a Mac), so the screen shows a key field instead of the Console
   button."). It is `claude::takes_key(claude::SignIn::Console)` in every `ClaudeStatus` the API builds,
   whatever the state: a platform fact, not a state. Add it to every constructor (`ready_status`,
   `subscription_refused_status`, `unavailable_status`, `stopped_sign_in_status`, the ones inline in
   `claude_check_in`, `claude_sign_in_in`, and any other `grep -rn "ClaudeStatus {" builder`).
2. **A new request DTO** in `dto.rs`:
   `pub struct ClaudeKeyRequest { pub api_key: String }` with
   `#[serde(rename_all = "camelCase", deny_unknown_fields)]` and `#[ts(export)]`, deriving
   `Deserialize` and `TS` only (no `Clone`, `PartialEq`, `Serialize` or derived `Debug`). Write `Debug`
   by hand so it prints `ClaudeKeyRequest { api_key: "hidden" }`, and a `Drop` that zeroizes `api_key`
   (`zeroize = "=1.9.1"` in `builder/api/Cargo.toml` if missing; the workspace already locks it).
3. **The API function** in `assistants.rs`, next to `claude_sign_in_in`:
   `pub fn claude_save_key_in(home, path, fallbacks, sign_ins: &ClaudeSignIns, mut request: dto::ClaudeKeyRequest) -> Result<dto::ClaudeStatus>`
   and `pub fn claude_save_key(request: dto::ClaudeKeyRequest) -> Result<dto::ClaudeStatus>` (the real
   home, `PATH` and fallbacks, `claude_sign_ins()`, as `claude_sign_in` does).
   - First move the key out: `let key = Secret::new(std::mem::take(&mut request.api_key));`
     (`voice_save::secret::Secret`).
   - Off a Mac (`!claude::takes_key(claude::SignIn::Console)`): `Err(failure(text::FAILED))`.
   - Take the same slot as a sign-in, under the same lock and with the same guard
     (`ClaudeSignInGuard`): signing out → `Err(failure(text::SIGN_IN_DURING_SIGN_OUT))`; a sign-in
     running → `Err(failure(SIGN_IN_BUSY))`.
   - `find_in` error → `Ok(unavailable_status(error))`. `status` signed in → `Ok(ready_status(status))`;
     status error → `Ok(unavailable_status(error))`.
   - `claude.save_key(home, key)`: `Ok(claude)` → `claude.status(home)` → `ready_status` when signed
     in (else `unavailable_status` of `text::KEY_REFUSED`). `Err(error)` → `Ok(dto::ClaudeStatus { subscription: false, ready: false, message: claude_message(error), note: None, can_sign_in: true, can_sign_in_with_subscription: claude::SUBSCRIPTION_OFFERED, console_takes_key: true })`.
   - The key is never logged, returned, or put in a `Failure`.
4. **The Tauri command** `claude_save_key(request: voice_api::dto::ClaudeKeyRequest)`, `async` like
   `claude_sign_in`, registered everywhere the lockdown test requires: `commands.rs`, the handler list in
   `main.rs`, `command_names.rs` (after `claude_sign_in_cancel`), `capabilities/default.json`
   (`allow-claude-save-key`), the generated permission file, and `parity.rs`
   (`app: "claude_save_key", cli: &[&["claude", "sign-in"]]`).
5. **The screen** (`ConnectClaude.vue`):
   - `backend.ts` gains `claudeSaveKey(request: ClaudeKeyRequest): Promise<ClaudeStatus>`;
     `tauri-backend.ts` calls `invoke<ClaudeStatus>('claude_save_key', { request })`; `test-support.ts`
     mocks it. Every `ClaudeStatus` literal in the UI and its tests gains `consoleTakesKey`.
   - When `!status.ready && status.canSignIn && status.consoleTakesKey`, show this form **instead of**
     the "Sign in with Anthropic Console" button (the subscription button and "Check again" stay as
     they are):
     ```html
     <form class="mb-3" @submit.prevent="saveKey">
       <label for="console-key" class="form-label">Anthropic Console API key</label>
       <input id="console-key" v-model="key" type="password" class="form-control" autocomplete="off" autocapitalize="off" spellcheck="false" aria-describedby="console-key-help" :disabled="savingKey" />
       <div id="console-key-help" class="form-text">Make a key at console.anthropic.com, under API keys. Voice keeps it in this Mac's Keychain and gives it only to Claude Code. What Claude Code does with it is billed to your Console account.</div>
       <button type="submit" class="btn btn-primary mt-3" :disabled="savingKey || !key.trim()">Save the key</button>
     </form>
     ```
     When `consoleTakesKey` is false the Console button shows exactly as today.
   - `saveKey()`: return if already saving or the field is blank; `savingKey = true`; clear
     `signOutError`/`signOutMessage`; `const apiKey = key.value.trim()`; **clear `key.value` before the
     call**; `status.value = await backend.claudeSaveKey({ apiKey })`; on a thrown failure, a status with
     `failureMessage(failure, "Voice couldn't keep your key. Close it and open it again.")`,
     `canSignIn: true`, `consoleTakesKey: true`, the rest false/null; `finally` `savingKey = false`. While
     saving, show a spinner line `Checking your key with Claude Code…` in place of the form.
   - The footer paragraph: when `status?.consoleTakesKey`, it reads `Voice never sees your password. On a Mac it keeps your Anthropic Console API key in the Keychain and gives it only to Claude Code. Its sign-in is separate from the Claude app and from the Claude Code you use yourself. Claude is the only choice for now. Other AI providers come later.`
     Otherwise it stays exactly as today.
   - Tabler classes only, as above; no new CSS.
6. **Three review fix-ups to VF5a**, in the same working tree:
   - `builder/agent/src/claude.rs` `sign_in_with`: the refusal is `if takes_key(sign_in)` alone
     (`!starts(sign_in)` is the same condition).
   - `find_in_impl`: `console_key::load(home)?` without the extra `map_err` (`load` already returns
     `KEY_UNREADABLE`).
   - `builder/api/src/assistants.rs` `claude_message`: drop `text::KEY_HOW` and `text::KEY_PROMPT`
     from the allow-list (they are prompts, never errors).

## 2. Tests, red first

Write each test, run it, and see it fail on its assertion before the code that makes it pass.

1. API, macOS (`builder/api/tests/`, the stub `claude` pattern its Connect Claude tests use; the
   agent's `test-stubs` keeps the key in a file in the test's home, never the Keychain):
   - `claude_save_key_in` with a valid made-up key, the stub reading signed in only when
     `ANTHROPIC_API_KEY` matches → a ready status; a following `claude_check_in` is ready too.
   - a bad shape → not ready, `message == KEY_SHAPE`, `console_takes_key` true, `can_sign_in` true.
   - while a sign-in holds the slot → `SIGN_IN_BUSY`; while signing out → `SIGN_IN_DURING_SIGN_OUT`.
   - every `ClaudeStatus` from `claude_check_in` has `console_takes_key == cfg!(target_os = "macos")`.
   - `format!("{:?}", request)` never contains the key.
2. App: the lockdown test passes with the new command (it fails first once `command_names.rs` lists it
   and nothing else does).
3. UI (`ConnectClaude.test.ts`, vitest): with `canSignIn` and `consoleTakesKey`, the key field
   (password type) and "Save the key" show and the Console button doesn't; the button is disabled
