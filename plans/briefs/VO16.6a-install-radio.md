# VO16.6a: Voice installs its Radio from the installer and on start

Built Claude-direct under the fallback rule (Codex is at its usage limit until 2026-11-18); this brief
records the decisions it was built from. Spec: lane V § VO16.6a, split from VO16.6; plan
`2026-11-10-shared-fleet-core.md` § *The install handshake* (VO16-D6). It builds on PB8.9c2's
`voice_api::radio::install`, which runs the copy of Radio beside Voice's own `voice` as
`radio install --app voice --app-version <v> --handler <voice>` and says each exit code as a fixed sentence.

## Decisions

1. **`voice radio install`**, beside `voice radio status` in `builder/cli/src/radio.rs`. It calls
   `radio::install` for `$HOME`, prints the sentence on success and exits 0; a failure goes through the
   CLI's usual `voice: <sentence>` on stderr and exit 1. No flags.
2. **The installer runs it once, after Voice.app is in place and before it opens Voice:**
   `"$installed/Contents/MacOS/voice" radio install`, so Radio's handler is the lasting copy in the
   Applications folder. Its own sentence passes straight through. When it fails (any exit), the installer
   adds one fixed line on stderr, `Voice is installed and works without Radio. It will try to install
   Radio again each time you open it.`, and still exits 0: Voice works without Radio.
3. **The app runs the same install once per start, on a thread of its own:**
   `voice_api::radio::install_on_start()` spawns a thread that reads `$HOME` and calls `install`, and
   returns its `JoinHandle` at once. The app's `main` calls it inside Tauri's `setup` hook and drops the
   handle, so the window never waits on it and its result is not shown (`voice radio status` says how
   Radio stands). Radio's handshake makes a same-or-newer daemon a no-op, so a drag-and-drop upgrade of
   Voice upgrades Radio on its next start and an ordinary start costs one quick check.
4. **No new sentences in `radio::text`.** The installer's line is the only new user-facing text.

## Tests (red first)

- `builder/api/src/radio/tests.rs`: `in_background`, the thread `install_on_start` runs on, given an
  install of a stand-in Radio that sleeps, returns at once, then joins to `INSTALLED` with Voice's argv
  recorded once. Its return type is the `JoinHandle`, so `install_on_start` can't run the install inline.
- `builder/cli/tests/radio.rs`: `voice radio install` without a copy exits 1 with `voice: <NO_COPY>` on
  stderr and nothing on stdout.
- `builder/app/tests/lockdown.rs`: `main.rs` calls `voice_api::radio::install_on_start()` exactly once,
  inside `.setup(`.
- `tests/mac_install_test.sh`: the stand-in app's `voice` records its arguments and exits with
  `FAKE_VOICE_EXIT`. A good install runs it once as `radio install` and prints its line; a failing one
  leaves Voice installed, exit 0, with the installer's line; a refused copy never runs it.
