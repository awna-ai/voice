# VO16.6b1 fix-up 1: the threat model says what Radio v0.3.0 runs, and a test pins Voice's refusal

Branch `lane-v1/VO16.6b1`, on top of `f88439a`. Read `plans/briefs/VO16.6b1-radio-v0.3.0-pin.md` first; this
fix-up **replaces its step 4 ban on `.ai/SECURITY.md`** for the three rows named below (that ban was the reviewer's
mistake).

## Why

The security review and the Verifier both found that Radio v0.3.0 is the first release whose daemon **runs an app's
recorded handler**. Its `message` op (Radio's `CONTRACT.md`, the `message` row and the *App messages* paragraph)
lets an accepted computer in the person's fleet send up to 8,192 bytes to an app; the daemon then runs that app's
handler, recorded at install, as `[<handler>, "message"]`, with the body on stdin, working folder `/`, and an
environment of only `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, the daemon's `HOME`, `RADIO_FROM_KEY`, `RADIO_FROM_NAME`
and `RADIO_MESSAGE_ID`; it kills the process group at 30 seconds or when stdout passes 4,096 bytes. Voice records
its own `voice` as that handler (`voice_api::radio::install`). Voice has no `message` subcommand, so today `voice
message` is refused by clap's argument parsing (exit 2, nothing on stdout) before Voice reads stdin or touches
`HOME`. The Verifier ran it that way with a scratch `HOME` and saw exactly that. Nothing pins it, and
`.ai/SECURITY.md` still says Radio runs nothing.

## Steps (test first)

1. **Red, then green, in `builder/cli/tests/radio.rs`.** Add one test,
   `radio_message_is_refused_without_reading_or_writing_anything`, beside the existing ones and using the same
   `Scratch` helper:
   - Run `env!("CARGO_BIN_EXE_voice")` with args `["message"]`, `env_clear()`, then only `PATH` set to
     `/usr/bin:/bin:/usr/sbin:/sbin`, `HOME` set to the scratch `home` folder, `RADIO_FROM_KEY` set to 64 `a`
     characters, `RADIO_FROM_NAME` set to `pebble`, `RADIO_MESSAGE_ID` set to 32 `0` characters, and
     `current_dir("/")`.
   - Write a JSON body on stdin (`{"kind":"seat_turn","room":"r1"}` is enough) through `Stdio::piped()`, then wait
     for the output.
   - Assert: the exit code is non-zero (`!output.status.success()`); stdout is empty; and the scratch `home` folder is
     still empty afterwards (`fs::read_dir(...).unwrap().next().is_none()`).
   - Prove it can go red: temporarily add a hidden `message` subcommand that prints `ok` (only in your working tree,
     never committed), watch the test fail, then remove it. Say in your summary what failed.

   to 1.10 (it can link computers, it is only older than this Voice), and reinstalling Voice may not help when the
